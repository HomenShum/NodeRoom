Below is the external-inspiration map we have built around NodeRoom. The through-line is:

> **NodeRoom = Attio-like context + Quadratic-like spreadsheet/artifact surface + BankerToolBench-grade evaluation + Convex live ledger + OKF portable knowledge + hybrid retrieval + banker-readable coach/review layer.**

Your own design notes framed the core agent-harness principle clearly: the model is the “brain,” while the harness owns tools, memory, state persistence, approval gates, circuit breakers, rollback, and safety.  Your professional workflow notes then grounded the target surface in spreadsheet-first company-research and finance/ops workflows with evidence-bearing writes, privacy boundaries, no-clobber mutation, and eval traces.

| **OpenRouter / adaptive model routing**                   | Route cheap tasks to cheap models and reserve strong models for semantic rebase / final reports.                                                                              | Research lane, collaboration lane, semantic rebase lane, formula/math deterministic lane; model/cost telemetry shown in Status Strip / analytics.                                                                                   |
| **Linkup**                                                | AI search API with standard/deep research modes for grounded company/market research.                                                                                         | Search tool for company product, pricing, funding, hiring, competitors, headwinds, source refs.                                                                                                                                     |
| **Gemini Embedding 2 / File Search**                      | Gemini Embedding 2 supports multimodal embeddings across text, images, video, audio, and documents; File Search offers managed RAG workflows. ([Google AI for Developers][6]) | Use Convex-native vector search first; optionally embed OKF/source chunks with Gemini. File Search is a possible managed retrieval adapter, not the source of truth.                                                                |
| **Cursor semantic search / Kuba Rogut retrieval framing** | Retrieval is not one vector call; it is semantic search, full-text search, glob, regex, filters, and iterative agent search.                                                  | NodeAgent retrieval loop: OKF semantic + full-text + metadata filters + graph/backlinks + spreadsheet search + literal source open + external fallback. Treat the Cursor metrics as directional unless original source is provided. |
| **Jeff Dean “right million tokens” framing**              | The goal is not to stuff everything into context; it is to retrieve the right subset.                                                                                         | OKF + Convex full-text/vector + evidence sufficiency + subagent evidence memos.                                                                                                                                                     |

# 4. Knowledge, retrieval, and source-evidence inspirations

| Reference                                   | What we extracted                                                                                                                                                                                                                                | NodeRoom version                                                                                                                                                  |

| **Google Open Knowledge Format**            | OKF is a vendor-neutral, human- and agent-friendly format: directories of Markdown files with YAML frontmatter; concepts link to each other as a graph; required `type` field; fields like title, resource, tags, timestamp. ([Google Cloud][7]) | **OKF is NodeRoom’s portable knowledge layer**: companies, sources, cells, metrics, charts, coach cues, traces, evals, review rounds, algorithms.                 |
| **LlamaIndex CitationQueryEngine**          | Citation-marked responses and source nodes that can be inspected. ([Developer Documentation][8])                                                                                                                                                 | Evidence Carousel: click a claim → literal source file/page/row/bbox + explanation of support strength.                                                           |
| **Convex vector search / full-text search** | Convex supports vector indexes and full-text search, so we may not need an external vector DB at first. ([Convex Developer Hub][9])                                                                                                              | Start with Convex-native `okfChunks`, full-text search, vector search, graph edges. Add external vector DB only after scale/features demand it.                   |
| **RAG discourse**                           | “RAG is dead” is too narrow if RAG means only top-k vector chunks.                                                                                                                                                                               | NodeRoom’s version is **agentic investigation**: generate candidate evidence, inspect top results, open literal files, produce evidence memos, then answer/write. |
| **OKF graph visualizer**                    | OKF includes reference graph-visualizer ideas for portable concept browsing. ([Google Cloud][7])                                                                                                                                                 | OKF Graph Artifact: Company → Source → Cell → Metric → Chart → Coach Cue → Trace → Eval.                                                                          |

# 5. Database, sync, streaming, and analytics inspirations

| Reference                                           | What we extracted                                                                                                                                                                                | NodeRoom version                                                                                                                                        |
| --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Convex optimistic updates**                       | Optimistic updates are temporary local client-cache edits that run when a mutation starts and reconcile with authoritative server data when the mutation completes. ([Convex Developer Hub][10]) | Chat bubbles, cell edits, queue toggles paint instantly; durable truth still commits through Convex mutation and app-level CAS.                         |
| **Convex Actions / Mutations / internal mutations** | Long external work belongs in Actions; durable writes belong in mutations/internal mutations.                                                                                                    | Agent LLM/search/provider work runs in actions; `write_locked_cell_results` / `applyCellEditCore` commit truth.                                         |
| **Convex persistent text streaming**                | Streams text to a client over HTTP while persisting on the server for reload/share. ([GitHub][11])                                                                                               | Agent narration streams live; spreadsheet truth commits as validated patches, not token-by-token cell updates.                                          |
| **Convex as OLTP vs ClickHouse as OLAP**            | Convex for live operational truth; ClickHouse for large analytical scans. ClickHouse is a column-oriented OLAP DB. ([ClickHouse][12])                                                            | Convex: rooms/messages/artifacts/cells/proposals/traces. ClickHouse: cost, latency, model route, retrieval analytics, no-clobber rate, source coverage. |
| **Supabase Realtime / WebRTC comparison**           | Raw row/WAL streams or peer streams are not enough for auditable collaborative artifacts.                                                                                                        | Use Convex for durable reactive ledger; optionally use ephemeral presence/soft-intent separately for cursor/active edit state.                          |
| **ClickHouse from AWS-Hackathon**                   | Non-blocking analytics event sink; telemetry must not take down the demo path.                                                                                                                   | `warehouseOutbox` → ClickHouse for agent cost, source coverage, retrieval hit/miss, no-clobber analytics.                                               |
| **Langfuse**                                        | Prompt/version/tool trace observability.                                                                                                                                                         | Future trace cockpit linked to Convex run IDs and ClickHouse analytics.                                                                                 |

# 11. Final synthesis: how all references collapsed into the current design

```text
LiveFlow          -> finance users need fast, reliable agentic workflows
Attio            -> objects + Universal Context + workflow agents
Quadratic        -> spreadsheet-native, code-based, auditable analysis
BankerToolBench  -> client-readiness and multi-file professional eval bar
Convex           -> live OLTP ledger + optimistic UI + actions/mutations
OKF              -> portable knowledge bundle for humans and agents
Gemini Embedding -> multimodal search substrate over OKF/source artifacts
LlamaIndex       -> citation/source-node inspection pattern
ClickHouse       -> analytics warehouse for cost/eval/retrieval/no-clobber
OpenUI           -> artifact rendering, proof cards, charts, UI panels
Linear           -> task ownership and review state
Cluely pattern   -> always-on coach, but transparent and auditable
frontend-slides  -> polished HTML deck
feature-walkthrough-gif -> live demo recording proof
```

The shortest final framing:

> **NodeRoom is a live AI diligence workroom: Attio-like context, Quadratic-like artifact work, BankerToolBench-grade proof, Convex-backed collaboration, OKF-packaged knowledge, and a banker coach that turns hidden agent work into evidence, review, and explanation.**
