## Debt 2 — Answer-key contamination in the flagship adapter is unreverted  (BLOCKING)

**Repo reality:**
- `btb_noderoom_agent/harbor_adapter.py` still contains the `is_*_task → write_*_package`
  dispatch (e.g. `write_comcast_take_private_teaser_package`, `write_greenbrier_cim_package`).
- The repo's **own** `docs/eval/BTB_GENERALIZATION_DIAGNOSTIC.md` names
  `harbor_adapter.py:4717` as *"the contamination to revert."*
- The honesty switch (`materializer_mode ∈ {replay, general-only}`) exists but the per-task
  dispatch is still reachable.

**Why it's blocking:** Solo Founder's thesis is literally *"the anti-cheat IS the product."*
Publicizing a reference adapter that hardcodes per-task answer-key writers refutes the pitch.

**Now a precondition of the proof, not a separate task.** An honest full-suite proof MUST be
generic-only, so the answer-key path cannot count. Defense-in-depth: the full-suite gate
(`bankertoolbench-fullsuite-gate.ts`) excludes any task whose receipt is not clean generic-only
from the 100, so contamination can't sneak into the flip even if the dispatch is still present.
Still close the hole at the source: make the `write_*_package` dispatch *throw* under
generic-only (hard gate), not merely "not selected."

**Mitigation (do at least a+b before publishing):**
- **(a)** Default the materializer path OFF via a `BTB_DISABLE_MATERIALIZERS` gate; report only
  generic-only numbers as the headline.
- **(b)** Label the materializer path in code + docs as *"diagnostic, not the reported number."*
- **(c, preferred for the public reference)** Revert the per-task dispatch entirely.

## Debt 3 — NodeMem recall-lift is unconfirmed in the committed artifact  (SHIP "IN PROGRESS")

**Claim in circulation:** *"bare/shadow 0.00 vs bounded/full 1.00 recall lift."*

**Repo reality:**
- `docs/eval/nodemem-benchmark-report.json` shows **only the "bare" variant ran** (1 run, mode=off).
- `e2e/nodemem-benchmark.spec.ts` defines a 4-variant A/B, but `convex/nodemem.ts` reads
  `process.env.NODEMEM_MODE` **once at startup on a shared backend** → without per-run isolation
  the variants can return identical results (this is the previously-found failure mode).
- Seed episodes are identical across non-bare variants → bounded/full differ only by token trim.

**Mitigation:**
- Re-run the 4-variant benchmark with **per-run mode isolation** (separate dev deployment per
  variant, or a per-request mode override) before publicizing any lift number.
- Until then describe NodeMem as *"memory model + deterministic compile + ranked retrieval;
  recall benchmark re-running with per-variant isolation"* — not a proven lift.

## The gate, in one line

> **Do not create the public NodeRL repo until Debt 1 (full-suite proof earned via the gate) and
> Debt 2 (generic-only hard-gate; contamination can't count) are settled. Debt 3 may ship as
> "benchmark in progress" provided no lift number is asserted.**

Debt 1 is now an execution effort, not a wording change: run the full suite generic-only, let
`bankertoolbench-fullsuite-gate.ts --write` flip `FR-020B` when (and only when) the receipts earn
it. The earned claim — *all 100 tasks executed + officially scored generic-only, mean reward X* —
is both true and stronger than an unverifiable "100/100 pass."
